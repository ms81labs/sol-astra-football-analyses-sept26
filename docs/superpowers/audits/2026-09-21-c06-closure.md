## Declared limits and remaining qualifications

Default diagnostic ceilings: 120 seconds, 1,920×1,080, four streams, 5-GiB input and 3,600 frames; 16-MiB producer payload assembly/conversion budget, 64 timing entries, 64-KiB diagnostic tail and 4-MiB captured command output. Job/stall/probe/export deadlines are 300/30/30/120 seconds. Child CPU soft/hard limits are 300/305 seconds, address space 4 GiB and regular-file size 8 GiB; two FFmpeg threads. These are explicit configured ceilings, not a promise all sources at the maxima meet a performance target.

The long-test receipt records 12,441,600 bytes for producer frame assembly/conversion and zero queued frames. That field excludes caller-retained frames, Python/runtime overhead, pipes and child RSS. Actual observed decoded work was 9,331,200,000 bytes. Limits/receipts must not be reinterpreted as a whole-process measured RSS claim.

Filesystem/network isolation is not provided by this launcher; allowed media protocols and rlimits are narrower controls. No full-match/live, macOS runtime, GPU, model-quality, production-policy or deployment approval is granted. No model/training/provider call, paid/GPU execution or live-store modification occurred. Final combined V3T50/browser and approved real-football baseline remain separate from this C06 closure.
